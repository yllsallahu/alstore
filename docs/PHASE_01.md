## 1. What this phase delivers

- Next.js 16 App Router application, React 19, strict TypeScript, Tailwind CSS 4, shadcn-style accessible primitives on Radix (`radix-ui`), Zod.
- Invitation-only login screen `/hyrje` **without bypass**: it validates input (Albanian errors) and then always refuses with an honest message, because personal accounts arrive in Phase 02. No public sign-up link or route exists.
- App shell (desktop sidebar, mobile header + modal menu, skip link) with the twelve sections: Ballina, Shitje e re, Faturat, Klientët, Blerje e re, Furnitorët, Stoku, Pagesat / Borxhet, ATK / EDI, Shpenzimet, Raportet, Cilësimet.
- Ballina shows the four large actions: Shitje e re, Blerje e re, Stoku, ATK / EDI.
- Every other section is an honest placeholder: "Ende jo aktiv" badge, empty state naming the planned phase, a **disabled** primary action, no inputs or forms. ATK / EDI shows "Eksporti ATK është në pritje të verifikimit".
- Loading (`loading.tsx`), error (`error.tsx`, `global-error.tsx`, shows only the error digest) and Albanian 404 (`not-found.tsx`, real HTTP 404) states.
- Environment validation (`src/lib/env.ts`), run at server start via `src/instrumentation.ts`; fails closed.
- Scripts: `dev`, `build`, `start`, `lint`, `typecheck`, `format`, `format:check`, `test`, `test:e2e`, `check`.
- Security headers (`nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Permissions-Policy`), `poweredByHeader: false`, `robots: noindex`.

No business modules, database, Supabase client, authentication backend, B2C, retail or POS controls.

## 2. Decisions

| Decision | Reason |
|---|---|
| **Development UI preview** (`UI_PREVIEW=true`) is the only way to see the shell before Phase 02. `getShellAccess` allows it only when `APP_ENV=development`; `parseServerEnv` rejects `UI_PREVIEW=true` for staging/production at boot. A permanent banner says "Pamje paraprake për zhvillim: pa llogari, pa të dhëna reale. Asnjë veprim nuk ruhet." | Spec requires shell screenshots and E2E, but no accounts exist yet. The login itself has no bypass. Phase 02 replaces this with real sessions and must remove or keep the preview dev-only. |
| `ISSUANCE_ENABLED` / `OFFICIAL_ATK_EXPORT_ENABLED` = `true` is rejected at boot | Fail closed: neither feature exists. Later phases relax this behind their gates. |
| One explicit route file per section instead of a dynamic `[modul]` route | With the loading boundary, a dynamic route streamed unknown slugs with HTTP 200; static routes give a real 404 and future phases replace one file each. |
| Light theme only; system font stack (no `next/font/google`) | Spec: dark theme optional; avoids build-time network calls and third-party font requests. |
| `lang="sq-XK"`, locale `sq-XK`, timezone `Europe/Belgrade` in E2E | Albanian UI; same timezone assumption as Phase 00 §8. |
| TypeScript **6.0.3**, ESLint **9.39.5** (not latest 7.x / 10.x) | `typescript-eslint` (via `eslint-config-next`) supports TS `<6.1.0`; React lint plugins declare ESLint ≤ 9. All versions pinned exactly. |
| `output: "standalone"` not set yet | `next start` does not support it; Docker image is Phase 19. |

## 8. Security notes and known issues

- `npm audit`: 5 high findings, all in **dev** tooling (`braces` stack-exhaustion DoS, GHSA-vfj7-8cjw-p6xm, pulled in by lint/test tooling); production dependencies: 0. `npm audit fix --force` would make breaking changes; left for QA/owner decision.
- The development preview is a deliberate, env-guarded exception (see §2). Risk: someone sets `UI_PREVIEW=true` with `APP_ENV=development` on a deployed server. Mitigation: Phase 19 deploys with `APP_ENV=staging|production`, where boot fails if the flag is set.
- No secrets read or printed. `.env` was not opened; Next loads it at build (`- Environments: .env`).
- Local Node is v26.10.0 while `.nvmrc` pins 22; all commands above ran on v26. `package.json` engines `>=22.12.0`.
- npm prints `Unknown env config "devdir"` from the owner's npm configuration; harmless.
- On this machine Playwright needs `PLAYWRIGHT_BROWSERS_PATH=0` (browser inside `node_modules`) because the sandboxed shell uses a temporary cache; outside the sandbox, plain `npx playwright install chromium` is enough.
